1. Information Architecture & Navigation Flow

Linear onboarding funnel into a tab-based authenticated app. Mobile container is fixed at max-width:480px.

Splash Screen (auto, ~6s) └─▶ Onboarding (3 screens, auto-advance 3.2s or tap Next/Skip) └─▶ Login ──────────────┐ │ "Create account"│ ▼ │ Registration │ │ OTP Verification │ └────────┬─────────┘ ▼ Dashboard (bottom nav home) ┌─────────────┬─────────────┬─────────┬──────────────┬───────────┐ ▼ ▼ ▼ ▼ ▼ Dashboard Incidents & Services Bill Consumption Help & FAQs outages │ │ │ │ ▼ ▼ ▼ ▼ Outage Map Service Requests Bills and Recent Bills Report an (request detail) Payments Issue Help Chat — reachable globally from the header bell / Help & FAQs Site Map — full index of every screen, linked for QA/dev nav

2. Screen-by-Screen Interactions & Field Validation

Splash Screen Auto-navigate

ElementBehavior
Logo + wordmarkFades in centered, slides left; wordmark types in letter-by-letter (16px, one line), tagline follows.
Progress barFills bottom-up over 2s after text animation completes. No user input.
NavigationAuto-advances to Onboarding at ~6s total. No tap/skip available.

Onboarding (3 screens) Auto-advance + manual

ElementBehavior
Step dotsActive dot (24px) fills with a 3.2s progress wipe; inactive dots 16px, static. Tapping Next resets the timer on the new step.
Next buttonAdvances step; on step 3 reads "Get started" and routes to Login.
Skip linkVisible on steps 1–2; jumps straight to Login.
Auto-advanceEach step auto-advances after 3.2s with no tap required; final step auto-finishes to Login.

Login Form

FieldValidation
Email *Required; must match standard email pattern. Inline error below field on blur if invalid/empty.
Password *Required, min 8 characters (enforced at Registration). Eye icon toggles visibility; 44×44px tap target.
Actions
Sign inIf "Ask for a code at sign-in" is off → Dashboard. If on (default) → sends a one-time code to the saved method and shows the code step in the same white panel (see Sign-in code).
Create accountSecondary (outline) button → Registration.
Forgot passwordOpens 6-digit OTP reset flow inline (prototype code shown for demo).

Sign-in code (multi-factor) Login step 2

The user picks one delivery method in account settings (Text message or Email). The sign-in screen never asks which method to use: after email and password, the code goes straight to the saved method. The code step replaces the email/password form inside the same white panel under the hero (no pop-up). On mobile the panel is full width; the hero (246px) stays on top.

ElementSpec / behaviour
Back to sign inLink, 14px / 600, #404293, arrow-left 16px. Returns to the email/password form and cancels the send and resend timers.
Heading"Enter your sign-in code" — 28px / 600, line height 1.3, -0.01em, #0B1D3A (same as "Welcome back").
Sending state (~1s)28px spinner (3px ring, #404293 on 18% tint) + "Sending your code by {text message | email} to {masked destination}…" 14px / 500, #6B7280.
Instruction"Enter the 6-digit code sent by {text message | email} to {masked}." 14px / 500, line height 1.55. Masked: +592 ••• 4408 / r••••••••@gmail.com.
Label"SIGN-IN CODE" — 12px / 700, uppercase, 0.08em (same as the "EMAIL" label).
Code boxes6 boxes, 52px high, 10px gap, radius 12px, fill #F9FAFB, 1px inset ring #D1D5DB, digits 20px / 700. Boxes share the width evenly (flex:1 1 0; min-width:0) — 49px wide at 390. Focus: 1.5px inset #404293 + 3px ring rgba(64,66,147,0.22). Error: fill rgba(220,38,38,0.06), ring #DC2626.
Error lineUnder the boxes, 13px / 600, #DC2626, role="alert".
Prototype hint"Prototype code: 123456" dashed box. Prototype only — remove in production.
Verify and sign inPrimary button, full width, 48px, pill. Opacity 0.45 and cursor:not-allowed until all 6 digits are entered, or while locked after 3 wrong codes.
Resend"Send a new code in 0:30" (14px / 500, #6B7280) counts down, then becomes the link "Send a new code" (14px / 600, #404293). Resending clears the boxes and resets attempts.
Footnote"Codes are sent by {method}, as set in your account settings (Account and notifications › Sign-in and security)." 12.5px, centred. There is no "use email/text instead" switch.
Input behaviour
TypingDigits only; typing moves to the next box; Backspace on an empty box clears the previous box and moves back; ← / → move between boxes; Enter submits; pasting a 6-digit code fills all boxes.
FocusFirst box is focused when the code step appears and after a wrong code.
Validation
Fewer than 6 digits"Enter all 6 digits."
Wrong code"That code is not right. 2 attempts left." → "That code is not right. One attempt left." Boxes clear.
3 wrong codes"Too many attempts. Send a new code to try again." Verify stays disabled until a new code is sent.
Correct codeDashboard. (Prototype: 123456.)
ProductionCode expiry of N minutes, server-side rate limits, account lockout policy and audit logging are set by the backend.
API placeholders
POST /auth/loginReturns { mfaRequired, channel, maskedDestination }.
POST /auth/mfa/sendSends (or resends) the code to the saved channel.
POST /auth/mfa/verifyChecks the 6-digit code; returns the session on success.
Accessibility
Code boxesaria-label="Code digit", inputmode="numeric", autocomplete="one-time-code", aria-invalid when there is an error.
MessagesSending text uses role="status"; errors use role="alert" so they are announced.
Implementation noteKeep the email/password form mounted but hidden (height:0; overflow:hidden; visibility:hidden) so the panel keeps its width, and give the code section width:0; min-width:100%. Keep the route/link to the Dashboard outside anything that unmounts.

Registration & OTP Verification

FieldValidation
Full name *Required, min 2 characters.
Email *Required, valid email format, checked for duplicate account (server-side).
Phone *Required, Guyana format (+592).
Password *Min 8 chars, 1 number — inline strength hint.
OTP (6 digits)Auto-advances focus per digit; paste supported; resend link rate-limited (60s cooldown).

9. Screen Templates & Layout Grid

Every main screen at the design size of 390 × 844px (iPhone 14/15 viewport), captured from the prototype. Grid markings are drawn over each screen. The side margins are measured from the screen itself: 24px on the sign-in flow, 16px inside the app. Inside the margins sits a 4-column grid with a 12px gutter (12px is the app's most used gap), plus an 8px rhythm grid. Green boxes give each button, field, card and header its measured height. Pink markers show the space between stacked components and orange markers show the gutter between side-by-side components. These are all read from the rendered screens. Use the toggles to show or hide each layer.
