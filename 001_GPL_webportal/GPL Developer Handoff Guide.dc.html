1. Information Architecture & Navigation Flow

Sign-in funnel into a signed-in app shell: a fixed 64px top bar, a 240px left sidebar (collapses to 64px) and a fluid content area with no maximum width. At 1440 and 1024 the sidebar is always visible; at 390 it is replaced by an “Open menu” button that opens a full-width drawer over a 42% scrim. The sign-in flow uses a split layout (hero panel + form panel) at 1440 and 1024, and stacks the hero above the form at 390.

Sign in ├─ “Forgot your password?” ─▶ Reset password dialog (email/mobile → 6-digit code → new password → done) ├─ “Create an account” ─▶ Registration (step 1 of 2) ─▶ OTP Verification (step 2 of 2) ─▶ Dashboard └─ “Sign in” ─▶ Dashboard App shell (every signed-in page) Top bar: GPL logo · collapse-menu button · Search (type-ahead) · Notifications (badge 3) · Profile menu Sidebar: Dashboard Incidents & outages ─▶ Report an Issue (tab) · Track My Reports (tab) · Outage map (dialog) Services (“My Requests”) ─▶ New Service Request (tab) · My Requests (tab) Bills ─▶ Current bill (tab) · Bill history (tab) Consumption Help & FAQs Global: GPL Assistant (help chat panel, opened from Report an Issue) · Outage map dialog Profile: connection summary (customer / account / meter / zone) · Account and notifications · Sign out Dashboard shortcuts Reported in your area card ─▶ “View all outages” ─▶ Incidents & outages Planned outage card ─▶ “View outage” / “View outage map” ─▶ Outage map dialog Amount due ─▶ “Download bill” · Recent bills ─▶ “View all bills” ─▶ Bills Recent requests ─▶ “View all requests” ─▶ Services Quick actions ─▶ Report an outage · Report a hazard · Download your bill · Check your consumption

2. Page-by-Page Interactions & Field Validation

Behaviour is taken from the prototype’s page sources and checked in the rendered prototype. Where the prototype only fakes a server step (sign-in, payments, lookups) that is said, so engineering knows the real rule must come from the API.

Sign in Form

ElementBehaviour & validation
Email addressPlaceholder “you@example.com”. Label 12px/700 uppercase. No client-side validation in the prototype — an empty form still signs in; real rules come from the auth API.
PasswordMasked; the eye button toggles type="password" ↔ text.
Reset dialog — step 1Email or mobile. Valid when it matches /^[^\s@]+@[^\s@]+\.[^\s@]+$/ or has ≥ 7 digits. Otherwise: “Enter the email address or mobile number on your account.” (shown on “Send reset code”, cleared on typing).
Reset dialog — step 26 single-digit boxes, digits only; typing advances focus, Backspace on an empty box steps back, pasting fills from the box pasted into. Fewer than 6: “Enter all 6 digits.” Wrong code: “That code is not right. Try again.” and the boxes clear.
Reset dialog — step 3New password ≥ 8 characters, else “Password must be at least 8 characters.”; confirm must match, else “Passwords do not match.”
Reset dialog — step 4Done state; closing resets every field and error.

Actions

  • Sign in → Dashboard
  • Forgot your password? → reset dialog (modal, stays on Sign in)
  • Create an account → Registration
  • Get help link in the footer

Registration Form · step 1 of 2

ElementBehaviour & validation
Find your GPL accountCustomer number (e.g. 118 4402), Account number (e.g. 40 2938 1), Meter number (e.g. 7719042). A sample bill image shows where each number is printed.
Your contact detailsFirst name, Last name, Mobile number (+592 000 0000), Landline + Ext. Mobile: ≥ 7 digits, else “Enter your full mobile number.”
Create your loginEmail: must match /^[^@\s]+@[^@\s]+\.[^@\s]+$/, else “Enter a valid email address, for example you@example.gy.” Password: 8–20 characters with a number and a capital letter, else “8 to 20 characters, with a number and a capital letter.” Confirm: “Both passwords must match.”
Security questionSelect with 5 options (“What is the name of your favorite pet?” …) and a free-text answer.
Paperless bills / Email consentOpt-in toggles (“Yes, send paperless bills”, “Yes, I consent”), off by default.
TermsCheckbox “I agree to GPL’s Terms & Conditions and Privacy Policy”; each link opens a modal with the clauses.
Error summaryErrors show only after “Continue”. A summary reads “One detail still needs your attention” / “N details still need your attention” and the page scrolls to it. Editing a field clears its own error. Fields marked * are required in the UI; the prototype checks formats only.

Actions

  • Continue (fixed footer bar) → OTP Verification when there are no errors
  • Already have a MyGPL account? Sign in → Sign in

OTP Verification Form · step 2 of 2

ElementBehaviour & validation
Delivery channelRadio cards: Text message (masked mobile, e.g. +592 •••••• 0000) or Email (masked, e.g. y••@example.com). Text message is selected by default.
Send verification codeShows a sending state for 1.1s, then the 6-digit entry.
Code boxesSame input pattern as the reset dialog, plus ← / → to move. Verify enables when all 6 digits are filled and the code has not expired.
TimersResend is available after a 30s countdown; the code expires after 10 minutes (600s).
Wrong code3 attempts. Message: “That code is not right. N attempts left before you need a new code.”; boxes clear and focus returns to the first box. Wrong boxes use the error background with a 1.5px border.

Actions

  • Send verification code
  • Verify → Dashboard
  • Change details → back to Registration
  • Switching channel during entry resets the code
